# Rule 1

## A Component Is Just A Function

Everything starts here.

```jsx
function Counter(){

    return <button>Click</button>;

}
```

React doesn't create an object.

It doesn't mutate this function.

It simply calls it.

```
Counter()

↓

Execution Context

↓

Variables

↓

Functions

↓

JSX
```

When state changes

React simply calls it again.

Nothing more.

## Every Render Is A New Function Call

# Rule 8

## Stale Closures Are Not Bugs

This surprises everyone.

They remember

# Rule 9

## Dependency Arrays Control Closure Lifetime

Consider

```jsx

```

Question.

Yes.

No.

Dependency arrays

They control

React's decision

or replace

closures.

# The Entire Book In Seven Sentences

1. Components are functions.
2. Every render is a new function call.
3. Every render creates new variables and new closures.
4. Closures always remember the render where they were created.
5. React preserves state outside your component and injects it into each render.
6. Hooks exist to manage identity and synchronization across renders.
7. Everything else in React is a consequence of these rules.

If you truly understand these seven sentences,

React stops feeling like a framework with dozens of APIs.

It starts feeling like a very logical system built on JavaScript itself.
