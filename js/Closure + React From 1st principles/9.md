# Question 1

Predict the Output

```jsx
function Counter() {

    const [count, setCount] = useState(0);

    function handleClick() {

        console.log(count);

        setCount(count + 1);

        console.log(count);

    }

    return (
        <button onClick={handleClick}>
            Click
        </button>
    );

}
```

---

## Think First

Don't answer immediately.

Ask yourself

Which render created

```
handleClick
```

Does

```
setCount()
```

modify

the current closure?

---

## Answer

Output

```
0

0
```

---

## Why?

Current render

```
count = 0
```

Closure

↓

```
count = 0
```

Calling

```jsx
setCount()
```

does not change

the current closure.

It schedules

another render.

The current closure

continues seeing

```
count = 0
```

## Rule 2

---

## Rule 3

---

## Rule 4

## Rule 5

Almost every React interview question can be solved by answering these five questions.

# The React Debugging Checklist

When something behaves unexpectedly, don't guess.

Walk through this checklist.

### 1. Is this value coming from state or a ref?

- State → Snapshot per render
- Ref → Shared mutable object

---

### 2. Which render created this callback?

Every callback belongs to one render.

---

### 3. Is this callback still alive?

If yes,

it still sees

its original variables.

---

### 4. Are my dependencies correct?

Wrong dependencies

↓

Old closure

↓

Stale values.

---

### 5. Am I accidentally creating a new object or function every render?

If yes,

referential equality fails.
