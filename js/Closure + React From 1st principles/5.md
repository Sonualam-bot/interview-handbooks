# Chapter 5

# useCallback — Function Identity, Closures, and Why React Keeps Creating New Functions

> "useCallback does **not** make your function faster.
>
> It makes the **reference** to your function stable."

This is probably the most misunderstood Hook in React.

Many developers think

> "useCallback caches a function."

Technically true.

Practically misleading.

To understand `useCallback`, we first need to understand something much deeper.

**Function Identity.**

# Functions Are Objects

This surprises many developers.

Functions are objects.

```js
function hello(){}

console.log(typeof hello);
```

Output

```

```

But internally

functions are objects.

They have

- memory
- properties
- identity

Example

```js
function a(){}

function b(){}

console.log(a === b);
```

Output

```
false
```

Different objects.

Different identity.

# Wait...

If React Returns The Same Function...

Doesn't That Mean

It Also Returns

The Same Closure?

Exactly.

This is the most important sentence

in this chapter.

React is **not**

creating

a new closure.

It is returning

the previous one.

That previous closure

still remembers

the variables

from the render

where it was created.

# Why Doesn't React Always Reuse The Same Function?

Suppose React ignored dependencies.

```jsx

    console.log(count);

},[count]);
```

Question.

How would

```

```

It couldn't.

Every callback

would forever remember

the first render.

Dependencies tell React

when the old closure

has become invalid.

# Does useCallback Improve Performance?

This is another common misconception.

People write

```jsx
useCallback(...)
```

everywhere.

Question.

Does React render faster?

Usually

No.

Creating functions

is extremely cheap.

The expensive part

is unnecessary child renders.

useCallback helps

only when

function identity matters.

---

# When Should You Use It?

Usually

when

- Passing callbacks to `React.memo` components
- Passing callbacks deep into the component tree
- Hook dependency stability
- Avoiding unnecessary subscriptions

Not

because

"creating functions is slow."

It isn't.

# Interview Questions

## Does useCallback stop React from creating closures?

No.

It allows React

to reuse

an existing closure

until dependencies change.

---

## What does useCallback actually cache?

The function object.

Not the result.

---

## Why can useCallback create stale closures?

Because React may keep returning

the same closure

created during an older render.

---

## Does useCallback make JavaScript faster?

No.

Creating functions

is already cheap.

Its purpose

is preserving

function identity.

---

## Difference Between useRef And useCallback

useRef

```
Stable Object
```

useCallback

```
Stable Function
```

Different problems.
