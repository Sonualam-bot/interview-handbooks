# Chapter 6

# useMemo — Value Identity, Expensive Computations, and Referential Equality

> "useCallback memoizes a function.
>
> useMemo memoizes the **result** of a function."

This sounds simple.

Unfortunately, it also causes one of the biggest misunderstandings in React.

Most developers think

> "useMemo is for expensive calculations."

That is only half the story.

The other half is **referential equality**.

---

# React's Solution

```jsx
const numbers=useMemo(()=>{

    return [1,2,3];

},[]);
```

Render 1

```
Array A
```

Render 2

Dependencies unchanged

↓

Return

```
Array A
```

Again.

Now

```
Old Props

↓

Array A



New Props

↓

Array A
```

Equal.

React.memo

can skip rendering.

# Mental Model

```

↓

↓

↓

↓
```

Notice something.

# Wait...

Does That Mean

The Callback Is A Closure?

Absolutely.

```jsx

    return price*quantity;

},[price,quantity]);
```

Question.

What is this?

```jsx
()=>{

    return price*quantity;

}
```

Answer

A closure.

It remembers

```
price

quantity
```

from

the render

where it was created.

# Important Difference

---

# Expensive Computation

Suppose

```jsx

    for(let i=0;i<1000000000;i++){

    }

    return 42;

}
```

Without useMemo

Every render

```

```

---

With useMemo


Future renders

```jsx

```

Question.

Did we save

No.

Computing

```

```

React still has to

- store dependencies
- compare dependencies
- maintain cache

Every Hook

# The Real Purpose

Many senior React developers

use useMemo

not because

the calculation

is expensive.

But because

the resulting object

must have

stable identity.

---

# Example

```jsx

    dark:true

};
```

Every render

```

Object B

Object C
```

React.memo

fails.

---

Instead

```jsx

    return {

        dark:true

    };
```

Now

# Interview Questions

## What does useMemo cache?

The return value

of the callback.

---

## Does useMemo prevent renders?

No.

It prevents

unnecessary recomputation

and

preserves value identity.

---

## Can useMemo create stale closures?

Yes.

If dependencies

are incorrect.

---

## Difference Between useMemo and useCallback

useMemo

↓

Stores result.

useCallback

↓

Stores function.

---

## Why do objects often need useMemo?

Because every render

creates

new object references,

causing referential equality

to fail.
