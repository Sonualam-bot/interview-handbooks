# Chapter 4

# useRef — Escaping React's Render Cycle

> "If every render creates a new closure, how can we ever access the latest value without creating a new closure?"

React's answer is

```
useRef()
```

This chapter is probably the most misunderstood Hook in React.

Most developers memorize

> "useRef stores a mutable value."

That sentence is true.

But it explains almost nothing.

By the end of this chapter you'll understand **why useRef had to exist.**

---

# The Problem

Let's revisit everything we've learned.

Every render creates

- a new Execution Context
- new variables
- new closures

Example

```jsx
function Counter() {

    const [count, setCount] = useState(0);

    let value = 0;

    console.log(value);

}
```

Question.

What happens to

```
value
```

after every render?

Most people answer

"It updates."

No.

It disappears.

---

# Why?

Remember.

A component is just a function.

```jsx
Counter();
```

creates

```
Execution Context A
```

Inside

```
value = 0
```

Function finishes.

Execution Context disappears.

---

React renders again.

```
Counter();
```

creates

```
Execution Context B
```

Again

```
value = 0
```

Not because React reset it.

Because JavaScript created

an entirely new variable.

---

# Visual Memory

```
Execution Context

↓

value = 0
```

Destroyed.

---

Render 2

```
Execution Context

↓

value = 0
```

Destroyed.

---

Render 3

```
Execution Context

↓

value = 0
```

Destroyed.

There is no connection between them.

# Let's Prove It

```jsx
function Counter() {

    let clicks = 0;

    function handleClick() {

        clicks++;

        console.log(clicks);

    }

    return <button onClick={handleClick}>Click</button>;

}
```

Prediction.

User clicks.

Output

```
1
```

React re-renders.

Clicks again.

Output?

Most beginners answer

```
2
```

Wrong.

Output

```
1
```

Again.

Why?

Because

```
clicks
```

belongs to

that render.

The next render creates

a completely different

```
clicks
```

variable.

---

# So What Do We Actually Want?

Sometimes we need

a value that

- survives renders
- does NOT trigger renders
- can be changed whenever we want

Normal variables fail.

State triggers renders.

We need something in between.

---

# React's Solution

```jsx
const ref = useRef(0);
```

Question.

What does React return?

Many people think

```
0
```

Wrong.

React returns

an object.

Conceptually

```js
{
    current: 0
}
```

Notice

```
current
```

is just

a property.

Nothing magical.

---

# Why An Object?

This is one of the smartest design decisions in React.

Suppose React returned

```js
0
```

instead.

How would React update it?

Numbers are primitives.

Every render

would receive

another primitive.

No persistence.

Instead React returns

an object.

Objects are referenced.

Remember our chapter on Objects.

Variables store

references.

Not objects.

---

# Memory Diagram

Render 1

```
ref

↓

Object A

↓

```

---

Render 2

Question.

New object?

No.

React returns

```

↓

↓

```

Same object.

Different render.

---

Still

```

```

This is the entire trick.

React does NOT recreate

the object.

It recreates

the variable

that points

to the object.

Remember Objects chapter?

# Why Closures Love Refs

Remember stale closures?

```jsx
setTimeout(()=>{

    console.log(count);

},3000);
```

Printed

old count.

Why?

Because

```
count
```

was a primitive

inside that render.

Now imagine

```jsx
const ref = useRef(0);

setTimeout(()=>{

    console.log(ref.current);

},3000);
```

Question.

What did the closure capture?

Did it capture

```
ref.current
```

?

No.

It captured

```
ref
```

which is

an object.

Objects are mutable.

The closure always has

the same object.

Only

```
current
```

changes.

---

# Memory Picture

```
Timeout Callback

↓

ref

↓

Object A

↓

current = ?
```

Three seconds later

```
current
```

may have changed.

The callback

still reaches

the same object.

Therefore

it sees

the latest value.

---

# This Is The Biggest Difference

Primitive

```
count = 5
```

Closure remembers

that variable.

---

Object

```
ref

↓

Object

↓

current = 5
```

Closure remembers

the object reference.

Not the property value.

The property

can change later.

---

# Demonstration

```jsx
const ref = useRef(0);

console.log(ref.current);

ref.current++;

console.log(ref.current);
```

Output

```
0

1
```

No render happened.

Why?

Because React

doesn't watch

```
current
```

React only knows

about

State

and

Props.

---

# Why Doesn't Updating current Cause A Render?

Suppose

```jsx
ref.current = 50;
```

Question.

How would React know?

It wouldn't.

React never intercepts

property assignments.

It simply gave you

an object.

You're mutating it.

JavaScript is doing

ordinary object mutation.

React isn't involved.

---

# This Is Why useRef Is Mutable

State

```
setState()

↓

React knows

↓

Render
```

Ref

```
ref.current = value

↓

Plain JavaScript mutation

↓

React knows nothing

↓

No render
```

---

# Common Beginner Mistake

```jsx
ref.current++;

return (

    <div>

        {ref.current}

    </div>

);
```

Question.

Will UI update?

No.

Because React

never re-rendered.

The object changed.

The UI didn't.

---

# When Should You Use useRef?

Whenever

the UI

does NOT depend

on the value.

Examples

- Timer IDs
- DOM elements
- Previous values
- WebSocket connections
- Mutable cache
- Scroll position
- Latest callback
- Interval IDs

---

# DOM Refs

One of the oldest uses.

```jsx
const inputRef = useRef(null);
```

React later stores

```
input element
```

inside

```
current
```

```
inputRef

↓

current

↓

<input>
```

Now

```jsx
inputRef.current.focus();
```

works.

Notice

No render required.

# Previous Value Pattern

A common interview question.

```jsx
const previous = useRef();
```

```jsx
useEffect(()=>{

    previous.current = count;

},[count]);
```

Question.

After render

what does

```
previous.current
```

contain?

The previous render's value.

Because we updated it

after rendering.

# Interview Questions

## Why doesn't useRef trigger re-renders?

Because updating

```
.current
```

is plain object mutation.

React does not track it.

---

## Why is useRef an object instead of a primitive?

Because React needs one stable reference that survives every render.

---

## Why does a stale closure still see the latest ref.current?

Because the closure captured the object reference, not the property value.

Every closure points to the same object.

---

## Does React recreate the ref object every render?

No.

React recreates

the variable

that points to the object.

The object itself

is preserved.

---

# One Sentence To Remember Forever

> **State gives you a new value every render.**
>
> **Refs give every render the same object.**

That single sentence explains almost everything about `useRef`.
